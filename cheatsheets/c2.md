# C2 — framework selection (the honest version)

> Authorized red-team engagements only.

## The uncomfortable truth
No **public** C2 stays un-signatured. Sliver got caught because it's popular and
open-source — vendors grabbed the default implants, wrote YARA/behavioral rules,
and shipped them. Havoc, Mythic's stock agents, Villain, everything public is on
the same treadmill. Swapping Sliver for "the next unsignatured framework" buys
you a few months until that one is popular too. **Framework choice is not what
keeps you quiet — how you build and operate the implant is.**

So the goal isn't "find the magic C2." It's: pick a framework whose *architecture*
lets you change what defenders signature, then actually change it.

## What actually moves the needle (in priority order)
1. **Custom / uncommon agent, not the default binary.** The default implant is
   what's signatured. Frameworks that decouple the agent from the server let you
   swap or write your own — that alone dodges the static rules.
2. **Malleable network profile.** Default JA3/TLS fingerprints, URIs, and
   headers are signatured too. Shape traffic to look like something boring.
3. **Redirectors + sane comms.** Domain fronting/CDN redirectors, long sleep,
   high jitter, egress over 443/DNS. Behavior gets you caught more than bytes.
4. **Loader/execution hygiene.** How the agent lands and runs (unbacked memory,
   known-bad API sequences) is what EDR flags at runtime — separate problem from
   the C2 itself, and the harder one.

## Frameworks worth adopting (all public, all open-source)
- **Mythic** — the right answer to your question. It's a *framework*, not one
  implant: server + a catalogue of interchangeable agents (Apollo/C#, Poseidon/Go,
  Athena, Merlin, …) and profiles, all Docker-managed. You run a less-common agent
  or write your own against a stable API, so you're not shipping the binary everyone
  has a rule for. Actively developed, big ecosystem.
- **Havoc** — modern, capable, good demon agent and UI. Popular now, so its
  defaults are increasingly signatured — treat it as "customize before use."
- **Empire / Starkiller** — still useful for quick PowerShell/.NET work and labs.
- Selection matrix: **thec2matrix.com** compares features/detections across ~50
  frameworks — use it to pick by capability, not hype.

## Recommended path
Stand up **Mythic** and run a non-default agent, then customize its profile. That
gets you off Sliver's signatured defaults with a platform built for exactly this,
instead of chasing a framework that'll be signatured next quarter.

```bash
# one-shot bootstrap (installs Docker if needed, builds, installs agent+profile, starts)
~/dotfiles/tools/mythic-setup.sh [agent] [profile]     # defaults: thanatos http
mythic status        # shell helper -> sudo ./mythic-cli status
mythic creds         # print UI url + admin login
```

Admin password (never hardcoded — your manager is the source of truth):
```bash
# pipe it straight from your manager (no prompt, nothing on disk after):
MYTHIC_ADMIN_PW="$(bw get password mythic)" ~/dotfiles/tools/mythic-setup.sh
# or run it plain and paste at the secure prompt.
# The bootstrap seeds .env before first start, then strips the plaintext once
# the account exists. Rotate a live instance in the UI (operator settings),
# not via .env — .env only sets the password at initial account creation.
```
Then in the UI (https://127.0.0.1:7443, user `mythic_admin`): generate a payload
from a *non-default* agent, edit the C2 profile's URIs/headers/jitter away from
stock, and front it through a redirector. The framework is the easy part.

The parts that genuinely evade a specific EDR (custom loaders, in-memory
execution, API-level evasion) are per-target engineering, not a checklist — scope
them to the actual target's defenses on the actual engagement.
